# 회계자료 검토 및 보고 보조 프로그램
### Accounting Review & Reporting Assistant

> 회계자료를 단순히 입력하는 것이 아니라,  
> **숫자 뒤의 근거를 확인하고 신뢰할 수 있는 자료로 정리하는 과정**을 돕는 프로그램입니다.

# 1. 왜 만들었나요?

회계 업무에서는 숫자가 맞는지만 확인해서 끝나지 않습니다.

예를 들어 지출 내역 하나를 검토할 때도 다음을 확인해야 합니다.

```text
언제 사용했는가?
금액은 맞는가?
무엇을 위해 사용했는가?
증빙은 있는가?
중복 거래는 아닌가?
공급가액 + 부가세 = 총액인가?
추가 확인이 필요한 거래는 없는가?
```

그리고 문제가 발견되면 다시:

```text
누가 확인할 것인가?
언제까지 확인할 것인가?
어떤 근거로 정상 처리했는가?
보완 요청은 했는가?
최종적으로 어떻게 처리됐는가?
```

를 관리해야 합니다.

이 프로그램은 이런 반복 검토 업무를 하나의 흐름으로 정리하기 위해 만들었습니다.

---

# 2. 한 문장으로 설명하면

> **Excel/CSV 회계자료를 업로드하면 검토가 필요한 항목을 자동으로 찾아주고,  
> 담당자 확인·증빙관리·체크리스트·월별보고·감사 대응까지 연결하는 프로그램입니다.**

---

# 3. 프로그램 흐름

```text
회계자료 업로드
      ↓
열 자동 인식 / 데이터 정리
      ↓
검토 Rule 실행
      ↓
누락 · 중복 · 오류 · 증빙 문제 탐지
      ↓
확인·보완 업무 생성
      ↓
담당자 / 기한 / 처리근거 관리
      ↓
제출 전 체크리스트
      ↓
월별 현황 및 보고 초안
      ↓
감사 대응 자료 / Excel 내보내기
```

단순히 오류를 표시하고 끝나는 것이 아니라  
**“발견 → 확인 → 처리 → 결과 기록”**까지 이어지도록 설계했습니다.

# 4. 주요 기능

## ① 회계자료 자동 정리

Excel 또는 CSV 회계자료를 업로드할 수 있습니다.

프로그램은 다음과 같은 항목을 표준화해서 관리합니다.

- 지출일자
- 금액
- 공급가액
- 부가세
- 거래처
- 사용목적
- 계정과목
- 부서
- 사용자
- 증빙번호
- 증빙여부
- 결제수단

---

## ② 회사마다 다른 열 이름 대응

실제 자료에서는 열 이름이 모두 같지 않습니다.

예를 들어:

```text
지출일자 = 사용일자
금액 = 결제금액
거래처 = 가맹점
사용목적 = 내용
계정과목 = 비용계정
증빙여부 = 첨부여부
```

처럼 표현이 다를 수 있습니다.

프로그램은 열 이름을 자동으로 인식하고,  
업로드 전 사용자가 직접 매핑을 확인하거나 수정할 수 있습니다.

같은 양식을 다시 업로드하면 이전에 확정한 **열 매핑 프로필**을 재사용할 수 있습니다.

---

# 5. 자동 검토 항목

기본적으로 다음과 같은 항목을 검사합니다.

| 검토 항목 | 설명 |
|---|---|
| 지출일자 누락 | 날짜가 없는 거래 확인 |
| 금액 누락 | 금액이 입력되지 않은 거래 확인 |
| 0원 / 음수 거래 | 확인이 필요한 특이 금액 표시 |
| 사용목적 누락 | 사용 사유가 없는 거래 확인 |
| 사용목적 너무 짧음 | 설명이 부족한 거래 확인 |
| 증빙 누락 | 증빙이 없는 거래 확인 |
| 증빙번호 누락 | 증빙 연결에 필요한 번호 확인 |
| 거래처 누락 | 거래처 정보 확인 |
| 계정과목 누락 | 계정과목 미입력 확인 |
| 공급가액 + 부가세 불일치 | 합계 검산 |
| 고액 지출 | 설정 기준 이상 거래 확인 |
| 정확 중복 | 동일 거래 가능성 확인 |
| 중복 의심 | 날짜·금액·거래처 기준 유사 거래 확인 |
| 미래 일자 | 잘못 입력된 날짜 가능성 확인 |
| 주말 지출 | 필요 시 Rule을 활성화하여 확인 |

> 이 기능들은 회계처리를 자동 확정하는 기능이 아니라  
> **사람이 먼저 확인할 거래를 빠르게 좁혀주는 기능**입니다.

# 6. 검토 Rule을 코드 없이 변경

회사마다 기준이 다르기 때문에 검토 Rule을 코드에 고정하지 않았습니다.

관리자 화면에서 다음을 변경할 수 있습니다.

```text
Rule 사용 / 미사용
중요도
기준값
안내문구
표시순서
고액 기준
최소 글자수
허용오차
```

예:

```text
고액 지출 기준
1,000,000원 → 300,000원
```

으로 바꾸면 다음 검토부터 새로운 기준이 적용됩니다.

간단한 사용자 정의 Rule도 추가할 수 있습니다.

# 7. 확인·보완 업무 관리

문제를 찾는 것만으로는 실제 업무가 끝나지 않습니다.

각 이슈에 다음 정보를 기록할 수 있습니다.

- 담당자
- 처리기한
- 중요도
- 처리상태
- 보완요청
- 확인완료
- 예외인정
- 처리근거 메모

예:

```text
[증빙 누락]

거래처 : 문구사
금액   : 77,000원
담당자 : 김대리
기한   : 2026-08-20

상태 : 보완요청
메모 : 법인카드 영수증 추가 제출 요청
```

---

# 8. 원본 자료 추적

검토 결과만 저장하면 나중에 원본을 다시 찾기 어렵습니다.

그래서 각 거래에:

```text
원본 파일명
원본 행번호
검토 Rule
발견 내용
처리상태
처리근거
```

를 연결합니다.

이를 통해:

> “이 오류가 원본 Excel의 어느 행에서 나온 것인가?”

를 다시 확인할 수 있도록 설계했습니다.

---

# 9. 증빙·문서 관리

회계자료와 관련된 문서를 등록할 수 있습니다.

예:

- 영수증
- 세금계산서
- 거래명세서
- PDF
- DOCX
- TXT 문서

증빙번호를 기준으로 거래와 문서를 연결할 수 있습니다.

예:

```text
회계자료 증빙번호
AUG-RC-009

        ↕

영수증 증빙번호
AUG-RC-009
```

현재 버전은 **증빙 존재 및 연결 관리** 중심입니다.

> OCR로 영수증의 금액·날짜·거래처를 자동 판독해 회계자료와 완전히 대조하는 기능은 아직 구현하지 않았습니다.

# 10. 제출 전 체크리스트

자료를 제출하기 전에 확인해야 하는 항목을 관리합니다.

예:

```text
☑ 미확인 오류가 없는가?
☑ 증빙 누락 건을 확인했는가?
☑ 고액 지출을 검토했는가?
☑ 중복 의심 거래를 확인했는가?
☑ 담당자 확인이 완료됐는가?
```

체크리스트 항목도 관리자 화면에서:

- 추가
- 수정
- 삭제
- 순서 변경

이 가능합니다.

---

# 11. 월별 현황 및 원인 확인

단순히 이번 달 총액만 보여주지 않습니다.

예:

```text
7월 총 지출 : 25,000,000원
8월 총 지출 : 31,000,000원

전월 대비 : +24%
```

그다음 증가 원인을:

- 계정과목
- 거래처

기준으로 확인할 수 있습니다.

예:

```text
전월 대비 증가 기여

임차료      +2,400,000원
교육훈련비  +1,100,000원
소모품비      +800,000원
```

즉,

> **“얼마나 변했는가?”뿐 아니라 “어디에서 변했는가?”**

를 확인할 수 있도록 만들었습니다.

# 12. AI 보고 보조

이 프로젝트에서 AI는 **숫자를 계산하거나 회계처리를 최종 확정하는 역할**을 맡지 않습니다.

계산과 오류 검증은 Python과 Rule이 담당합니다.

AI 활용 영역은:

- 월별 보고 문장 작성 보조
- 확인 요청 문구 작성
- 미결사항 요약
- 문서 설명 정리
- 감사 대응 설명 초안

등의 **커뮤니케이션 보조**입니다.

현재 버전에서는 검증된 데이터를 기반으로 AI에 전달할 수 있는 프롬프트를 생성하는 구조이며,  
외부 LLM이 회계자료를 자동으로 판정하도록 만들지 않았습니다.

# 13. 대시보드

대시보드에서는 먼저 처리해야 할 항목을 볼 수 있습니다.

예:

```text
전체 거래        1,280건
검토 필요           63건
증빙 누락           21건
중복 의심            9건
기한 경과            4건
담당자 미지정         6건
```

장식용 차트보다:

> **무슨 문제가 있는가? → 무엇을 먼저 처리해야 하는가?**

를 빠르게 확인하는 데 초점을 맞췄습니다.

# 14. UI 디자인

UI는 닷슬래시대시(DotSlashDash)의 시각적 분위기에서 아이디어를 얻어  
회계 프로그램에 맞게 새롭게 구성했습니다.

그대로 복제하지 않고 다음 요소만 참고했습니다.

- 강한 타이포그래피
- 넓은 여백
- 카드 중심 정보구조
- 단순한 기하학적 요소
- 모노톤 기반
- 필요한 부분에만 강한 포인트 컬러

회계 프로그램에서는 가독성을 우선해:

```text
오프화이트 배경
+ 차콜
+ 코발트 블루
+ 오류 Red
+ 확인 Yellow
```

방식으로 적용했습니다.

# 15. 코드 없이 화면 문구 수정

프로그램을 운영하면서 문구 하나 바꾸기 위해 코드를 수정하지 않도록 설계했습니다.

관리자 화면에서 다음을 변경할 수 있습니다.

- 프로그램 이름
- 메뉴 이름
- 메뉴 순서
- 메뉴 표시 / 숨김
- 화면 제목
- 설명문
- 카드 이름
- 버튼명
- 안내문구
- 체크리스트
- 검토 Rule

즉,

> **개발자가 없어도 운영자가 회사 상황에 맞게 화면과 규칙을 변경하는 것**

을 목표로 했습니다.

# 17. 가장 쉽게 테스트하는 방법

## STEP 1

`01_정상자료_2026-07.xlsx`를 업로드합니다.

정상적인 회계자료가 어떻게 처리되는지 확인합니다.

## STEP 2

`02_오류포함_검토연습_2026-08.xlsx`를 업로드합니다.

이 파일에는 일부러 여러 오류를 넣었습니다.

예:

```text
날짜 누락
금액 누락
증빙 누락
VAT 불일치
고액 거래
중복 거래
미래 일자
```

## STEP 3

`확인·보완 업무` 메뉴에서 발견된 이슈를 확인합니다.

담당자와 기한을 지정하고 상태를 변경해봅니다.

## STEP 4

증빙 문서를 등록합니다.

예:

```text
05_AUG-RC-009_영수증.txt
증빙번호 = AUG-RC-009
```

## STEP 5

`월별 보고`에서 7월과 8월의 차이를 확인합니다.

## STEP 6

제출 전 체크리스트와 Excel/감사 대응 자료를 확인합니다.

# 18. 로컬 실행 방법

## Windows

저장소를 다운로드합니다.

```text
Code
→ Download ZIP
```

압축을 푼 뒤:

```text
run.bat
```

을 실행합니다.

---

## 직접 실행

Python 3.11 이상을 권장합니다.

패키지 설치:

```bash
pip install -r requirements.txt
```

기존 FastAPI 화면 실행:

```bash
uvicorn main:app --reload
```

브라우저:

```text
http://127.0.0.1:8000
```

---

# 19. Streamlit 실행

Streamlit 포트폴리오 화면을 로컬에서 실행하려면:

```bash
streamlit run streamlit_app.py
```

브라우저가 자동으로 열리지 않으면:

```text
http://localhost:8501
```

로 접속합니다.

# 20. Streamlit Community Cloud 배포

GitHub 저장소를 Streamlit Community Cloud와 연결합니다.

배포 설정:

```text
Repository
→ 자신의 accounting-review-assistant 저장소

Branch
→ main

Main file path
→ streamlit_app.py
```

그다음 **Deploy**를 누릅니다.

> Streamlit Community Cloud의 로컬 SQLite 파일은 영구 저장을 보장하지 않습니다.  
> 따라서 현재 공개 버전은 포트폴리오 데모 용도로 사용하는 것을 권장합니다.

실제 회사 운영용으로 확장할 경우 PostgreSQL / Supabase 등의 외부 DB 연결이 필요합니다.

# 22. 프로젝트에서 보여주고 싶은 역량

이 프로젝트의 목적은 단순히 웹 화면을 만드는 것이 아닙니다.

## 회계자료 정확성

누락·중복·금액 오류를 체계적으로 검토합니다.

## 데이터 정리

회사마다 다른 Excel 구조를 표준화합니다.

## 감사 대응

원본과 처리근거를 연결해 추적할 수 있도록 했습니다.

## 업무 프로세스 개선

```text
문제 발견
→ 담당자 확인
→ 보완
→ 완료
→ 이력 저장
```

으로 연결했습니다.

## 보고 역량

검토 결과를 월별 현황과 보고자료로 정리할 수 있도록 했습니다.

## AI 활용

AI에게 회계 판단을 맡기기보다  
검증된 데이터를 바탕으로 설명·요약·보고 업무를 보조하도록 역할을 분리했습니다.

## 사용자 편의성

운영자가 코드를 수정하지 않고 프로그램의 주요 문구와 검토 기준을 바꿀 수 있도록 했습니다.

---

# 23. 프로젝트 핵심 메시지

> **“회계는 숫자를 입력하는 업무가 아니라,  
> 숫자 뒤의 근거를 확인하고 신뢰할 수 있는 자료로 정리하는 일이다.”**

이 프로그램은 이 생각을 실제 업무 흐름으로 구현해보기 위해 제작했습니다.

---

# 24. 현재 구현 범위와 한계

이 프로젝트는 **포트폴리오용 MVP / Prototype**입니다.

현재 구현되어 있지 않거나 추가 검증이 필요한 기능:

- 실제 ERP API 연동
- 실제 법인카드 시스템 연동
- 사용자 로그인 / 권한관리
- 다중 사용자 동시 작업
- OCR 기반 영수증 자동 판독
- 영수증 금액·날짜·거래처 자동 대조
- 세법 위반 자동 확정
- 자동 분개 확정
- 실제 생성형 AI API 직접 연동
- 기업용 영구 DB

특히 프로그램이 표시하는 `검토 필요`는:

> **회계 오류가 확정됐다는 뜻이 아니라 사람이 추가로 확인해야 할 거래**

라는 의미입니다.

---

# 25. 앞으로의 확장 방향

```text
OCR 증빙 판독
        ↓
거래 ↔ 증빙 자동 대조
        ↓
회사규정 Rule Builder
        ↓
사용자 로그인 / 권한
        ↓
ERP / 법인카드 연동
        ↓
외부 DB
        ↓
LLM 보고 보조
        ↓
실제 회계자료 대규모 검증
```

정확성이 검증되지 않은 자동화보다  
**단순하지만 검증 가능한 기능을 먼저 구현하는 것**을 개발 원칙으로 두었습니다.

---

## 마무리

회계자료 검토에서 중요한 것은 단순히 많은 오류를 찾는 것이 아닙니다.

```text
무엇이 문제인지
↓
왜 확인해야 하는지
↓
누가 확인할지
↓
어떻게 처리했는지
↓
어떤 근거가 남았는지
```

를 연결하는 것이 중요합니다.

이 프로젝트는 반복적인 회계 검토 업무를 줄이면서도  
**최종 판단과 책임은 사람이 유지하는 구조**를 목표로 만들었습니다.
